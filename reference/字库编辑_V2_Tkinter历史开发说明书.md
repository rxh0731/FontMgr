## 一、项目总体目标

将现有单体脚本（9179 行）升级为**专业化字库生产管理系统**。

**核心解决：**
- 海量数据管理（支撑单字库 1 万+ 图片，一字多形）
- 导入流程自动化（逐字寻优 + MD5 去重 + 状态追踪）
- 简繁导出（按需输出简体或繁体命名的成品字库）
- 高效编辑体验（会话恢复、快速定位、批量操作）

### 4.2 状态机

```
待导入(灰) ─→ 草稿(橙) ─→ 已审(蓝) ──→ 已定稿(绿)
   ↑              ↑              │   ↗        │
   └──────────────┴──────────────┘ (一致性调整) ┘
           (任一级别可退回重处理)
```

| 状态 | 含义 | 颜色标识 |
|------|------|---------|
| **待导入** | 导入失败或用户取消，留待重试 | 灰色 |
| **草稿** | 导入成功但未审核 / 重处理后回退 / 低分未达标 | 橙色 |
| **已审** | 人工审核通过，可进入一致性调整 | 蓝色 |
| **已定稿** | 经一致性调整（可选）后最终确认，导出时包含 | 绿色 |
| **(一致性调整)** | ✦ 非状态，是已审→已定稿之间的推荐操作环节 | — |

**流程说明**：
- 已审的字可以直接标记定稿（跳过一致性调整），适用于单字或少量字的项目
- 建议在批量定稿前，先进入一致性调整视图进行排版校准
- 一致性调整不改变状态，仅修改文件像素/变换参数
- 调整完毕后再手动标记定稿

旧格式映射：`未审核 → 草稿`，`待复核 → 草稿`，`已审核 → 已审`。

### 4.2.1 状态与目录对应关系

每个变体在不同状态下，其文件分布在四个目录中：

| 状态 | `源文件备份/` | `标准底图/` | `去杂中间/` | `定稿成品/` |
|------|:---:|:---:|:---:|:---:|
| **待导入** | ✅ | ❌ | ❌ | ❌ |
| **草稿** | ✅ | ✅ | ✅ | ❌ |
| **已审** | ✅ | ✅ | ✅ | ❌ |
| **已定稿** | ✅ | ✅ | ✅ | ✅ |

**四个目录的定位：**

| 目录 | 序号 | 定位 | 写入时机 | 是否可变 |
|------|:---:|------|---------|:---:|
| `源文件备份/` | ① | 原始文件的只读保险，永远不动像素 | 导入阶段复制 | ❌ 只读 |
| `标准底图/` | ② | DPI 统一 + 极性反相 + 墨色对齐后的归一化 PNG | 导入阶段归一化 | ❌ 只读 |
| `去杂中间/` | ③ | 去杂管线输出，可被重处理覆盖 | 导入寻优完成时 /「应用模板」重跑时覆盖 | ✅ 可覆盖 |
| `定稿成品/` | ④ | 经过全部编辑（修复笔、变换调整）后的最终 PNG | **仅变体标记为「已定稿」时**保存 | ✅ 每次定稿覆盖 |

**四个目录组成流水线：**
```
源文件备份/ ──(归一化)──→ 标准底图/ ──(去杂管线)──→ 去杂中间/ ──(编辑+定稿)──→ 定稿成品/
   ① 只读               ② 只读                ③ 可覆盖                 ④ 成品
```

**导出逻辑**：直接读取 `定稿成品/` 目录下的所有文件即可，无需查状态字段。该目录天然就是"成品清单"。

### 4.3 字形归属判定

- 默认取文件名首字作为归属字（如 `一-1.png` → 归属"一"）
- 导入时检测：若首字不在常用汉字范围（Unicode 0x4E00~0x9FFF），放入「未分类」组，用户手动指定
- 同一汉字的多张图片自动归入同一字形组，生成不同的变体 ID

### 4.4 文件命名规则

沿用 V1 的 `{首字}-{序号}` 规则（按首字分组，组内排序后递增编号）。命名规则分三层：

| 层 | 命名方式 | 说明 | 示例 |
|----|---------|------|------|
| **磁盘文件名** | `{归属字}-{序号}.png` | 导入时按首字分组、组内排序编号，后三个目录统一 `.png` | `一-01.png`、`羅-03.png` |
| **JSON 变体 ID** | `{Unicode}_{hash8}` | 内部唯一标识，用于跨表关联 | `4e00_a1b2c3d4` |
| **UI 显示标签** | 同磁盘文件名（去掉扩展名） | 缩略条/字符树展示，与磁盘文件名一致 | `一-01`、`羅-03` |

**四目录文件对照**（以源文件 `D:\原图\阿.jpg` 为例）：

```
源文件备份/          标准底图/              去杂中间/              定稿成品/
  阿-01.jpg          阿-01.png              阿-01.png              阿-01.png
  (保留原格式，         (DPI归一化后            (去杂管线输出           (编辑定稿后
   原样复制，           灰度→PNG，               RGBA·PNG)             RGBA·PNG)
   只读保险)            只读底图)

  文件主体相同          阿-02.png              阿-02.png              阿-02.png
  (仅序号递增)          (第二个变体，            (第二个变体)            (第二个变体)
                        同首字新序号)
```

**核心规则**：
- 导入时按文件名首字分组 → 组内自然排序 → 从 1 开始编号
- 同一首字多张图 → 序号自动递增（`阿-01`、`阿-02`、`阿-03`...），绝不重名
- `源文件备份/` 保留原格式（`.jpg`、`.tif`），其余三个目录强制 `.png`
- MD5 去重时，完全相同的图自动跳过，不消耗序号

**变体 ID 生成**：`hash8` 取标准底图 PNG 的 MD5 前 8 位。同一张图在任何时候导入，ID 都相同，天然支持去重。

### 4.5 变体删除后的命名一致性

变体的 `{首字}-{序号}` 是**写入磁盘的固定名称**，JSON 中记录文件名，排序在运行时动态计算。

```
原有 3 个变体：
  字形组索引["一"] = ["4e00_a1", "4e00_b2", "4e00_c3"]
  磁盘文件：             一-01.png   一-02.png   一-03.png

追加导入 2 张新图（"一"字的新变体）：
  新文件自动编为 一-04.png、一-05.png（接已有序号之后）
  字形组索引["一"] = [...原有... , "4e00_d4", "4e00_e5"]
  磁盘文件：                                 一-04.png   一-05.png

删除中间变体（一-02）：
  磁盘：一-02.png 移至回收站，其余文件保持原名不变
  字形组索引["一"] = ["4e00_a1", "4e00_c3", "4e00_d4", "4e00_e5"]
  显示排序：             一-01      一-03      一-04      一-05

  序号出现空洞（一-02 空缺），这是预期行为
  —— 因为序号是定稿时写入磁盘的固定名，不因删除而重排
```

**规则**：
- 序号写入磁盘后永不改变（防止定稿成品文件路径失效）
- 删除中间变体导致序号空洞，属正常情况
- UI 显示按字形组索引数组顺序展示，不自动补洞
- 新增变体时取「已有最大序号 + 1」，不填补空洞
- 未来如有拖拽排序需求，排序信息记录在 JSON 中，文件名不变

## 六、核心工作流

### 6.1 导入工作流（强制逐字寻优 + 分批追加）

**入口 A：新建字库**（引导页卡片墙 →「✨ 新建字库」）
**入口 B：追加导入**（主界面菜单栏「字库 → 追加导入」/ 字符树右键「🆕 追加变体」）

两种入口复用同一套导入引擎，区别仅在于：新建字库是首次导入，追加导入是在现有字库上增量添加。

#### 单次导入流程

```
① 导入向导
   用户选择源目录 → 设置 DPI/画布 → 输入字库名
   　　　　　　　　　　　　　　
② 扫描阶段（极快）
   扫描所有图片 → 计算 MD5 → 与库内现有哈希比对 → 自动跳过重复
   已存在的文件列表在向导中清晰展示，用户可手动勾选强制重新导入
   　　　　　　　　　　　　　　
③ 阶段 1a：墨色预检（只读，~0.01s/张）
   逐图判定极性（黑底/白底）+ 文字墨色中位 → 全批最深字为墨色基准
   　　　　　　　　　　　　　　
④ 阶段 1b：归一化 + 预处理固化（~0.03s/张）
   复制原始图 → DPI 统一缩放 → 按各图极性反相 → 墨色归一到全批基准
   → 输出为 `标准底图/` 目录下的归一 PNG

⑤ 阶段 2：逐字寻优 + 全尺寸执行（~0.1~0.7s/张，多线程）
   每张图：_auto_analyze → _auto_build_candidates → 缩略图跑分
          → 不达标则梯度派生加试 → 最优方案全尺寸执行
          → 输出到 `去杂中间/` 目录

⑥ 结果入库
   所有图片状态初始为「草稿」
   导入阶段失败的图片状态为「待导入」
      —— 文件仅存在于 `源文件备份/`，无归属字，不进入字形组索引
      —— 在主界面顶部仪表板中有「待导入」计数，点击可查看待导入列表
      —— 列表中每项显示文件名、失败原因，支持「重试」或「移除」
   成功图片按文件名首字生成字形组索引
   写入独立 JSON
```

#### 分批追加逻辑（已有字库 1000 字，新导入 500 字）

这是最常见的增量场景。用户已有一个大容量字库，后续又有新图片要入库。

```
已有字库：字形组索引含 1000 个汉字
新图片：500 张，文件名首字各不相同

追加导入向导：
  ① 扫描 500 张，计算 MD5，与库内现有哈希比对
       ├─ 60 张哈希已存在（完全重复）→ 自动跳过，在摘要中列出
       ├─ 200 张首字不在已有字形组中（"罗"、"罗"→"羅"等新字）
       │     → 正常走全流程，从阶段 1a 到入库
       │     → 生成新变体 ID → 创建新字形组 → 状态「草稿」
       │
       └─ 240 张首字已存在（"一"、"二"等库内已有字）
             → 正常走全流程，从阶段 1a 到入库
             → 生成新变体 ID → 追加到已有字形组 → 状态「草稿」
             → 例："一"原有 3 个变体，新增 2 张 → 变为 5 个变体

  ② 结果摘要：
     ┌─────────────────────────────────────────────┐
     │ 导入完成                                     │
     │                                             │
     │ 总计: 500 张                                │
     │ ✅ 成功: 440 张（新字 200 · 已有字追加 240）  │
     │ ⏭ 跳过(重复): 60 张                         │
     │ ❌ 失败: 0 张                                │
     │                                             │
     │ [查看导入详情]         [关闭]                 │
     └─────────────────────────────────────────────┘
```

**关键规则**：
- 同一张图片（MD5 相同）不会在同一个字库中出现两次
- 同名首字的新图片自动归入已有字形组，作为新变体
- 变体 ID 用 `{汉字Unicode}_{哈希前8位}` 生成，天然唯一
- 追加导入不会影响已有变体的任何状态

#### 「追加变体」快捷入口（仅对单个字）

用户右键字符树中某个字 →「🆕 追加变体」：

```
右键"一" → 追加变体
    │
    ▼
┌──────────────────────────────────────┐
│  为一"追加新变体                     │
│                                      │
│  已有一"变体: 3 个                   │
│  · 一-01 [已审]                     │
│  · 一-02 [已定稿]                   │
│  · 一-03 [草稿]                     │
│                                      │
│  选择要导入的文件:                    │
│  [选择文件...] (支持多选)            │
│                                      │
│  ▸ 选择的文件将自动走寻优管线         │
│  ▸ 文件名首字无需为"一"（已指定归属字）│
│                                      │
│       [取消]          [开始导入]      │
└──────────────────────────────────────┘
```

- 与批量导入不同，快捷入口**已指定归属字**，文件名首字可以不是目标汉字
- 复用导入流程的阶段 1a→1b→2→入库，结果直接追加到当前汉字组

### 6.2 编辑工作流

```
                              ┌─────────────────┐
                              │  一致性调整(可选)  │
                              │ 网格并排 · 对齐校准 │
                              └────────┬────────┘
                                       │
待导入 ─→ 草稿 ──→ 已审 ──────────────┴──→ 已定稿
  ↑         ↑        │                        │
  └─────────┴────────┘                        │
     (重处理/重导入退回)                       │
                                              ↓
                                          导出 ✓
```

**主编辑区操作**：
- 程序启动时，读取上次打开字库的 `会话` 字段，自动恢复到上次编辑的字和变体位置
- 缩略条切换变体
- 修复笔/橡皮擦修补瑕疵
- 变换调整：缩放/旋转/偏移/扭曲/斜切
- 状态推进：草稿 → 标记已审 →（可选：一致性调整）→ 标记定稿

**未保存提醒**：
- 修复笔修改、变换参数调整等操作在内存中进行，只在「标记定稿」时才写入磁盘
- 底部状态栏在有未保存修改时显示 `● 未保存` 标记（橙色圆点）
- 切换变体 / 切换汉字时如有未保存修改，弹出确认对话框：「当前变体有未保存修改，是否保存？[保存] [放弃] [取消]」
- 崩溃恢复：重启后会话恢复到最近打开的汉字，但内存中的编辑操作丢失，需重做
- 不引入自动保存机制（保持简单，后期按需添加）

### 6.3 应用模板（精准重处理）

- 选中当前变体（或 Ctrl/Shift 多选缩略条中的变体）
- 右侧面板「换方案」→ 选择实验室保存的模板
- 系统原地重跑去杂管线，仅覆盖选中变体的优化图
- 变换参数（偏移/缩放等）保留，修复笔操作清零
- 状态回退至草稿，弹窗告知用户修复笔已被清除
- **旧定稿成品文件处理**：状态回退时，`定稿成品/` 中的旧文件**不删除**，保留作为历史版本。用户下次重新定稿时覆盖写入

### 6.4 一致性调整（网格编辑，移植自原程序，基本不改逻辑）

#### 功能定位

对「已审」和「已定稿」的变体进行**批量位置/大小/旋转一致性校准**。
在网格视图中并排展示多张图片，逐一或批量调整变换参数。调整结果**烘焙回写入目录**，不改变变体状态：

- 原状态为「已审」→ 写回 `去杂中间/`，状态不变
- 原状态为「已定稿」→ 写回 `定稿成品/`，状态不变

> 一致性调整是排版校准工具，不应该自动推进状态。用户需显式操作「标记定稿」才写入 `定稿成品/`。

> **来源**：此功能直接移植原程序的 `_on_adjust_pos` ~ `_adjust_save` 全部逻辑（约 1600 行），核心交互和渲染管线基本不做修改。

#### 入口

菜单栏「工具 → 一致性调整」，或右侧工具面板中的快捷按钮。

#### 界面布局

```
┌──────────────────────────────────────────────────┐
│ ← 返回    🎯 一致性调整   字库: [▼]  字库信息     │
│ ☐ 编辑模式    💡 Alt+滚轮=缩放 | 拖拽移动 | ...   │
├──────────────────────────────────────────────────┤
│                                                  │
│   网格画布（可滚动）                               │
│   ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐           │
│   │      │ │      │ │      │ │      │           │
│   │ 一   │ │ 二   │ │ 三   │ │ 四   │           │
│   │      │ │      │ │      │ │      │           │
│   └──────┘ └──────┘ └──────┘ └──────┘           │
│   ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐           │
│   │ 五   │ │ ...  │ │ ...  │ │ ...  │           │
│   └──────┘ └──────┘ └──────┘ └──────┘           │
│                                                  │
├──────────────────────────────────────────────────┤
│  行: [4] 列: [4] [更新]     ◀ 上一页 第 1/1 页 下一页 ▶  [💾 保存] │

```

#### 文件来源

| 变体状态 | 读取目录 | 调整后写回 | 说明 |
|----------|---------|-----------|------|
| **已审** | `去杂中间/` | `去杂中间/` | 审核通过但未定稿，调整去杂结果 |
| **已定稿** | `定稿成品/` | `定稿成品/` | 已定稿的成品微调 |

- **草稿和待导入不参与一致性调整**：草稿尚未审核，待导入未完成导入
- 调整不改变状态，用户调整完毕后在主编辑区手动标记定稿

#### 核心功能

**① 可配置网格布局**
- 用户自定义行列数（行 1~50，列 1~50），点击「更新」实时重建
- 田字格等比缩放（按字库画布宽高比），自适应窗口宽度
- 滚轮纵向翻页，按当前行高平滑步进

**② 编辑模式（PS 风格自由变换）**
- 勾选「编辑模式」后，每张图显示 8 个角/边手柄 + 旋转手柄
- 支持操作：
  - **移动**：田字格内直接拖拽
  - **等比缩放**：拖拽四角手柄（以对角为锚点）
  - **单向拉伸**：拖拽边中点手柄
  - **旋转**：定界框外区域拖拽
  - **扭曲**：Ctrl + 角手柄拖拽（透视变换，OpenCV 实现）
  - **斜切**：Ctrl + 边中点拖拽
  - **缩放**：Alt + 滚轮（当前鼠标悬停的图片）

**③ 撤销机制**
- Ctrl+Z 撤销变换操作，按文件维护撤销栈（最多 20 个快照）
- 保存参数快照 + 原图副本，支持扭曲操作的回退

**④ 翻页与未保存保护**
- 翻页/切换字库/返回时，如有未保存修改，弹出确认对话框

**⑤ 保存烘焙**
- 只处理被修改过的图片（`_adjust_modified` 集合），不重写整页
- 统一渲染管线：原始图 → scale → stretch → rotate → distort → 合成输出
- 按实际文字包围盒检测超格，必要时扩展画布
- 田字格中心坐标写入 PNG 元数据（`grid_center`），下次加载时恢复
- 保存后自动同步哈希值，清理缓存

#### 渲染管线

```
原始图（裁剪副本，永不修改）
  │
  ├─ scale × stretch → 缩放拉伸
  ├─ rotate → 旋转（expand=True，以包裹旋转后全图）
  ├─ distort/skew → 透视变换（如有四角偏移）
  │
  └─ 合成到画布 → PNG + grid_center 元数据
```

#### 与主编辑区的区别

| | 主编辑区 | 一致性调整 |
|--|---------|-----------|
| 展示 | 单张大画布 | 多张网格并排 |
| 操作对象 | 单个变体 | 当前页所有变体 |
| 输出 | `去杂中间/` → 待定稿 | 直接写 `定稿成品/` |
| 用途 | 修笔画、调效果 | 统一大小和对齐 |

> **移植要点**：在新架构中，将 `_adjust_*` 系列方法整体提取到 `ui/adjust_page.py`，数据适配改为读写 `字库/xxx/xxx.json` + `定稿成品/` 目录。渲染、交互、保存逻辑不做更改。

### 6.5 导出

- 顶部「导出」下拉：
  - **导出简体字库**：成品文件以简体字命名（利用简繁映射表反查）
  - **导出繁体字库**：以繁体字命名
  - **导出全部（保持原名）**：以原始文件名导出
- 导出时仅包含「已定稿」状态的变体
- 输出为一个压缩包或独立文件夹，含 PNG + 索引文件

## 七、独立功能模块

### 7.1 实验室（模板生成器）

- 入口：菜单栏「工具 → 实验室」
- 功能：沿用当前 VerifyDialog 核心逻辑（选样图 → 调五层参数 → 实时预览 → 保存模板）
- 与当前 TemplateDialog 合并为单一界面
- 保存的模板写入 `配置/优化模板.json`，立即可在主编辑区的「换方案」中调用

### 7.2 文字统计

- 入口：菜单栏「工具 → 文字统计」
- 功能：完整保留当前文字统计页（选择经文文件 → OCR/文本提取 → 字符统计 → 字库缺失对比 → 导出）
- 作为独立工具存在，不依赖当前打开的字库

### 7.3 简繁映射管理器

- 入口：菜单栏「工具 → 简繁映射管理」
- 功能：表格展示全部映射关系，支持筛选「未确认」项
- 批量设置简繁对应关系
- 优先级：用户手动修改过的映射（标记 `user_edited`），不再自动覆写

## 九、技术选型

| 项 | 选择 | 理由 |
|----|------|------|
| GUI 框架 | Tkinter | 保持当前框架，不引入新依赖 |

| 缩略图缓存 | 内存 Dict，最多 200 条 LRU | 当前已实现，升级参数即可 |
| 并发处理 | ThreadPoolExecutor | 导入寻优、缩略图生成 |
| 数据安全 | 原子写入 + .bak 备份 | 当前已实现，延续 |
