## 启动程序

双击 `启动字库编辑_PySide6.bat`。首次运行会自动创建 `.venv` 并安装 `requirements.txt` 中的依赖。

Windows 开发版和单文件便携版统一使用“彩色方块字”图标。程序在创建 `QApplication` 前设置 FontMgr 专用 AppUserModelID，Qt 运行时组合载入 PNG 与多尺寸 ICO；仓库根目录的 `FontMgr.spec` 同时嵌入 PNG 运行时资源和 ICO 可执行文件资源，避免窗口标题栏、任务栏或 EXE 文件显示 Python、PyInstaller 或 Windows 默认图标。该配置不会自动生成便携版。

当前首页将“新建字库”作为制作流程第 `0` 步；没有字库时仅该步骤可用，选择已有字库后可继续进入添加、优化、审核、协调和导出。所有写入均限定在本项目字库目录内，旧版 `D:\Code\FontEditor` 保持只读不变。

图片实验室是独立整图功能，定位为 Photoshop 精修前的自动预处理，不读取字库数据库、阶段目录或字形状态。它以原稿路径、处理参数和原图归一化人工笔画组成单文件 `.fontlab` 项目，始终保持原稿不变；预览只保留约 2200 像素长边的工作副本，完整输出在后台按重叠分块生成。智能清理不预设图片是黑白、灰度或彩色，而是结合 Lab 多通道局部背景、明暗双向结构、颜色差异、笔画尺度细节、有限距离种子重建和保守文献边界，优先避免误删浅色、残损和彩色文字；红色待核对区域只提示证据不足的位置。清除背景工具增加白色遮盖，保护文字工具擦除遮盖并显露原稿，`Ctrl+滚轮` 缩放、普通滚轮滚屏、`Ctrl+Z` 撤销、`Ctrl+S` 保存项目。主输出为原稿锁定层、白色清理层和独立笔画修补层组成的 PSD/PSB，自动保留原稿 DPI 和 sRGB 配置；普通导出仍可选择白底清理效果或 RGB 固定白色、Alpha 表示覆盖强度的透明清理层。PSD 超过单边 30,000 像素或预计接近 2 GB 时自动改为 PSB。全部输出先写同目录临时文件再原子替换，停止时不会覆盖已有目标文件。

算法调研以 [DocRes](https://github.com/ZZZHANG-jx/DocRes)（CVPR 2024，MIT）和 [DocEnTR](https://github.com/dali92002/DocEnTR)（ICPR 2022）为主要学习模型参考。DocRes 功能完整但需要 PyTorch 与外部权重，且文档外观重建存在改写历史笔画的风险；DocEnTR 面向 DIBCO 二值化，但仓库未提供明确可集成许可。因此当前默认实现使用可解释且可回退的传统算法，不引入生成式重绘；学习模型接口留作后续在真实样本集完成字形保真评估后的可选增强。

从首页进入新建字库、字库添加、自动优化、手工审核、整体协调、字库导出、通用经文排版或定制经文排版时，主窗口在页面同步初始化阶段统一显示 Windows 系统等待光标，并先处理一次排除用户输入的界面事件，确保旋转圆圈立即可见且不会因重复点击重入；页面可操作、拒绝打开或发生异常后均恢复普通光标。长时间扫描和图片处理仍使用各页面原有后台任务与进度显示，等待光标不替代真实进度。

原“经文排版”功能现统一显示为“通用经文排版”，默认输出文件基础名也改为“通用经文排版”。模板保存在程序数据库 `配置/fontmgr.sqlite3`；现有 `配置/通用经文排版模板.json` 或旧的 `配置/排版模板.json` 只在数据库尚无对应记录时导入，模板交换文件仍使用 JSON。

首页在“通用经文排版”后提供“定制经文排版”。定制模式固定竖排、从右向左；每个非空正文行对应一列，空行分隔版面。每块版面分别设置单元格、基准列字数与行距、固定列距及边距；实际列字数不同时优先调整行距，行距不足时缩小该列单元格高度。字图按记录的物理毫米尺寸换算为当前画布像素，不使用源图 DPI 与输出 DPI 的比值；系统字库以建库毫米尺寸为准，外部字图从文件物理元数据换算，缺失时保留原像素。正文版数多于参数版数时，多出的正文明确标记为忽略且不生成。右栏使用“第 1 版 / 第 2 版 / ＋ / 输出参数”单层页签，新增版面始终插入输出参数之前，预览翻页与对应版面页签同步。定制模板与通用模板相互独立，均保存在程序数据库中。

## 当前工作区交接（2026-08-15）

- 当前自动优化阶段检查点命名为“自动优化0812”；该检查点在 81 项回归通过时建立，后续研究从本节记录的算法与性能状态继续。
- 当前分支为 `main`，存在尚未提交的功能修改；新会话必须先阅读差异，不得还原或覆盖。
- 自动优化候选已区分“原图直接采用”“仅背景透明”和“寻优优化”，并按有效透明区、白底清理程度及背景污染情况把原图归为“已有透明区 / 白底已清理 / 未处理截图”；分类类型、置信度、处理类型和评分方式会随方案持久化。有效透明背景必须具有 `Alpha <= 5` 的强透明证据；正常尺寸图片要求同一个外缘强透明连通域触达画布四边，近乎不透明 Alpha、单边透明带、互不连通的角块和纯内部透明块都不能触发直接采用。前两类在人工工作台分别默认采用原图或仅背景透明结果，候选区仍至少保留一张实际经过算法处理的寻优结果；第三类只显示寻优结果。安全寻优结果始终优先，只有全部处理结果均未通过结构保护时才显示风险最低的实际优化结果，并标记为“结构需人工核对”。
- 已有有效透明区先执行共享的增强 Alpha 轻度去杂。系统保留按笔画尺度确认的主体和抗锯齿边缘；重复出现且远小于点画尺度的高 Alpha 微小域不再因单个高 Alpha 像素受到保护，单个可能属于点画的微小域仍保守保留。清理后继续审计高 Alpha 微小域：安全且清理充分时批量快速采用；仍有成片残留或删除区域存在结构歧义时自动转入完整寻优。单字重新生成候选复用同一轻度去杂能力，并继续提供完整寻优候选供比较。对“小品-庆兰”1841张含透明层源图的只读分流为原图快速采用181张、增强轻度去杂1385张、完整寻优275张，约85%的透明图仍走快速路径。
- Photoshop TIFF 首版只解码 8 位 RGB、单个可见 `normal` 图层、完整 Alpha/R/G/B、未压缩或 PackBits 通道；图层边界、通道长度、逐行长度及重新合成的白底图必须全部与 TIFF 主图一致。画布和图层均限制为最多 16 Mi 像素、单边不超过 32768 像素，单通道不超过 24 MiB，图层数据约不超过 96 MiB；多图层、蒙版、ZIP、超限或任何不一致均无副作用回退，不会凭标签直接采用。
- 自动优化会识别黑底白字等反相原图并校正为白底深字，源文件保持不变，校正信息随候选方案保存。
- 自动优化处理引擎默认使用“无学习模型”；模型注册、三类输出协议、结果校验、缓存隔离和方案追溯接口已经预留，后续安装模型后可直接加入选择列表。
- 学习模型只提供前景概率、二值掩码或清洁灰度；候选派生、结构保护、评分、Pareto 排序和全尺寸复核仍由统一传统寻优管线完成。继续探索固定使用候选保存的模型版本、指纹和参数。
- 寻优参数按原图尺度自适应；明确低对比图片才启用受限 CLAHE、背景校正和 Triangle 路线，普通图片不进入这些分支。
- 新建与追加导入页已改为三栏图片字符校对；歧义卡片可选择候选或在红色输入框中人工输入。新建字库的成品宽高按 `毫米 = 像素 ÷ DPI × 25.4` 双向联动：修改像素或 DPI 时立即更新两位小数的毫米值，修改某一轴毫米值时按当前 DPI 将该轴像素取最近整数，换算期间使用锁避免递归触发。目录扫描会在工作线程同步准备小尺寸 `QImage` 预览，扫描达到总数后继续进入“正在生成校对列表”第二阶段；三栏卡片按约 12 毫秒时间片轮转生成并持续更新进度，最后一批布局完成后才开放搜索和导入。取消、返回或重新扫描会使旧代次结果失效，避免大量图片在进度达到 `N/N` 后长时间阻塞界面。实际写盘导入使用包含代次、专属取消事件和精确创建目录的不可变任务上下文；导入中请求返回首页会先安全停止并保存已完成项目，任务收尾后才离页，迟到信号不得清理或改写新任务状态。
- 简繁候选识别使用官方 OpenCC，并同时合并 `s2t`、`s2tw`、`s2hk`、项目明确映射和项目歧义表；相同候选自动去重，人工复核卡片只显示可选字符，并始终允许保留原字或人工输入，不显示歧义来源说明表。OpenCC 只提供候选，不自动替用户决定古文用字；依赖缺失或转换失败时扫描明确失败，不把未识别字符静默当作正确结果。

- 批量手工审核启动前会说明自动通过不能替代逐字判断以及可能遗漏缺损、误删、污点、大小或视觉中心问题，确认框只提供“确定 / 取消”，默认及 `Esc` 均为取消。运行区提供“停止批量审核”；已完成字形保留，当前单字事务完整提交或回滚，未处理字形继续保持待审核，停止完成后统一恢复页面控制。
- 字库导出已改为与整体协调一致的三栏工作台，但导出不构成第四个制作阶段。左侧采用同字父组和“字形与文件 / 协调状态 / 提示 / 导出”子项，只显示已经完成手工审核、获准进入整体协调阶段的字形；状态筛选仅为“全部（本阶段） / 待协调 / 已协调”，搜索用于导航并保留排序。已有成品显示最终图片，待协调项回退显示人工稿或自动优化稿，不再用系统字体冒充字形；辅助提示只展示，不参与筛选。“可导出 / 不可导出”由独立导出审计给出，不替代“待协调 / 已协调”。左栏只为可见区和少量后续项后台解码，使用 256 项 LRU、路径修改时间与大小签名及页面代次隔离。中间为默认每行 8 个且列宽均分的全库滚动预览；田字格严格使用字库设置的画布宽高，外围白色工作区在水平和垂直方向均为田字格的 `130%`，二者同中心并整体等比适配卡片。普通成品按田字格像素尺度显示，带对称透明扩展的成品按“实际画布”延伸到外围工作区；缺少尺寸记录的旧成品保持比例并在田字格内居中，不强制拉伸。右侧提供“按照字库参数”“去除透明区”和“自定义参数”三种 PNG 导出方式。自定义模式可设置 DPI、宽、高，并选择按完整图片或实际文字区域等比缩放居中。顶部另以带文字的绿点或红点表示全库是否可导出；绿色要求全部字形完成整体协调并通过完整导出审计，红色表示仍有未完成或异常字形，颜色不是唯一信息来源。页面后台执行成品内容和已有 MD5 的深度核对，核对期间禁止导出；红色状态必须中文确认后才会只导出核对通过的成品，没有有效成品时禁止启动。中间预览采用虚拟列表、可见区预取、最多 2 个后台解码线程和按实际可用物理内存计算的字节 LRU，非方形图片保持比例居中，离页会停止任务并释放缓存。启动后台导出前会统一预检目标目录同名文件，并逐项提供“覆盖 / 跳过 / 取消”；勾选“为所有项目执行此操作”后，覆盖或跳过会应用到剩余冲突，取消则不会启动后台任务。覆盖项会先在同卷临时目录备份，提交失败时恢复原文件并移除本批新增文件；预检后发生变化或新出现且未经授权的同名文件仍会安全拒绝。批次导出继续使用临时目录、部分导出白名单和源图尺寸硬上限，失败或取消不留下部分结果，目标路径、同名文件和成品来源均经过安全校验。
- 自动优化、手工审核和整体协调的搜索栏采用统一交互：输入框右侧提供“搜索”按钮，按回车或点击按钮后执行搜索，输入过程不自动刷新字形列表。搜索范围仅包含归属字、字形编号和文件名，不匹配“已审核”等主状态或辅助提示。
- 三个工作台每次执行新的文字搜索都从当前结果第一项重新定位，并同步刷新中间工作区及整体协调页码，不能沿用上一次查询的旧选择造成列表与内容不一致；删除全部搜索文字时立即恢复当前阶段和状态筛选下的全部字形，无需再次点击“搜索”。自动优化的迟到候选结果继续按任务代次丢弃，手工审核切换字形继续执行未保存稿保护。
- 自动优化、手工审核、整体协调和字库导出的具体字形统一通过字形列表右键菜单提供“修正字形名称”入口。系统保持稳定 `变体ID`，事务化同步六阶段现有文件名、SQLite 记录和字形组索引；图片内容和三阶段状态不变。普通失败完整回滚，进程异常退出后按图片事务清单恢复。
- 本次 SQLite 改造后的完整回归为 `750/750` 通过。专项覆盖程序级五类配置导入、字库创建与一次性导入、重复打开、失败回滚、语义核对、数据库完整性、无 JSONL 批处理、图片事务前滚与回滚、首页摘要缓存及三个制作阶段的停止和异常恢复。
- `字库/测试/测试.json` 与 `.bak` 是现有测试进度，未经确认不得还原。
